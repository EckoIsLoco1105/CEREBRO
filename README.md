# C.E.R.E.B.R.O

C.E.R.E.B.R.O (Course Evaluation, Review Engine, and Brain-Testing Review Organizer) helps students organize courses and topics, track review progress, and practise with quizzes.

## Quick start

You can run the frontend without an account or backend:

1. Install Node.js if it is not already installed.
2. Open PowerShell in the project folder.
3. Run `npx --yes http-server . -p 8080`.
4. Open `http://localhost:8080`.

The blank API URL in `config.js` means **demo mode**. Courses, topics, quiz results, theme, and recent activity are saved in this browser only. They are not shared across browsers or devices.

## Features and where data goes

| Feature | Demo mode | Signed-in mode |
|---|---|---|
| Courses, topics, review status | This browser's local storage | MySQL, separated by account |
| Quiz history | This browser's local storage | MySQL, separated by account |
| Recent activity and theme | This browser's local storage | Still browser-local |
| PDF, TXT, and Markdown resources | Not available | Stored with the course in MySQL |
| AI quizzes and saved reviewers | Generic sample quizzes only | Generated by Groq using course objectives and uploaded text |

PDFs must contain selectable text; scanned/image-only PDFs are not supported. Each upload is limited to 10 MB and extracted text to 200,000 characters. Up to 18,000 characters from a course's resources are sent to Groq when generating a quiz or reviewer. Review AI output before relying on it.

## Publish a static demo on GitHub Pages

GitHub Pages can host the frontend but **cannot run the Node API or MySQL**. The static demo is the easiest first release:

1. Create a GitHub account if needed, then create a new repository.
2. Upload the project files and folders from this directory. Keep `index.html` at the repository root. Do not upload `server/node_modules/` or any `.env` file.
3. In the repository, open **Settings → Pages**.
4. Under **Build and deployment**, choose **Deploy from a branch**, select the branch you uploaded (usually `main`) and the **/(root)** folder, then save.
5. Wait for the Pages deployment to finish. Open the published URL shown on the Pages settings screen.

For this mode, leave `window.CEREBRO_API_URL = "";` in `config.js`. The site works as a browser-local demo; login, shared accounts, uploads, and AI generation are not available. GitHub Pages URLs for project repositories usually include the repository name after the account name.

## Enable accounts, cloud storage, uploads, and AI

These features need **three separately configured services**: the GitHub Pages frontend, a Node.js host for `server/`, and a reachable MySQL 8-compatible database. AI features also need a Groq API key.

1. Provision MySQL and create a database/user for the API. Apply `server/schema.sql` to that database. Keep the database reachable only from the API host where possible, and use the database provider's TLS settings.
2. Deploy the contents of `server/` to a Node.js host such as Render. Use Node.js **20.16–20.x or 22.3+**. On the host, set the service root to `server`, install dependencies with `npm install`, and start it with `npm start`. The API listens on the host's `PORT`.
3. Set `JWT_SECRET` to a unique random value of at least 32 characters, and set the database credentials, `FRONTEND_ORIGIN`, and `GROQ_API_KEY` in the API host's private environment-variable settings. Set `DB_SSL=true`; if your database provider requires its own CA certificate, put the certificate PEM in `DB_SSL_CA`. Never put secrets in frontend files or GitHub.
4. Set `FRONTEND_ORIGIN` to the exact published website origin, including `https://` but not a path. For example, use `https://account.github.io`, not `https://account.github.io/project/`.
5. In `config.js`, set `window.CEREBRO_API_URL` to the API's public **HTTPS** base URL. Publish that frontend change to GitHub Pages.
6. If using Render, add a health check path of `/api/health`. Open `<API-URL>/api/health`; `{"status":"ok"}` means the API can reach MySQL. Then test account registration, sign-in, course creation, and quiz history on the published website.

The browser sends uploaded course excerpts to the configured Groq API when generating AI content. Check your providers' privacy, retention, and usage terms before uploading sensitive or copyrighted course material.

## Run and debug the API locally

The API requires its own environment settings and a working MySQL database:

1. In `server/`, run `npm install`.
2. Copy `server/.env.example` to `server/.env` and replace the example values with your private database, JWT, frontend-origin, and optional Groq settings. Do not commit `.env`.
3. Apply `server/schema.sql` to the database selected by `DB_NAME`.
4. Start the API from `server/` with `npm run dev` (restarts after code changes) or `npm start`.
5. Check `http://localhost:3000/api/health`. The default allowed frontend origin is `http://localhost:8080`.
6. Set `window.CEREBRO_API_URL = "http://localhost:3000";` in `config.js`, and serve the frontend at `http://localhost:8080`.

Useful checks from the project root:

```powershell
node --check .\script.js
node --check .\server\server.js
```

In the browser, press **F12** and use **Console** for JavaScript errors and **Network → Fetch/XHR** for API status and response details. Check the API host's logs for database or Groq errors. Never share passwords, login tokens, `.env` files, or API keys in screenshots or bug reports.

## Important security and deployment notes

- GitHub Pages files are public. Never put `JWT_SECRET`, `DB_PASSWORD`, or `GROQ_API_KEY` in `config.js` or any frontend file.
- Passwords are stored as bcrypt hashes. API data routes require a signed-in user and check record ownership.
- Use HTTPS for the public site and API. Restrict database access to the API host and configure TLS as required by your provider.
- Reapplying `server/schema.sql` creates the resource/reviewer tables and updates the custom-color column for an existing database.
- This project has not been verified against your production hosting, database, or AI credentials. Test those integrations before sharing the full service publicly.
